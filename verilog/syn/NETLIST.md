# Reading the netlists Vivado generates

**English** | [日本語](NETLIST.ja.md)

When you build and synthesize the block design with `create_bd.tcl` (see [`README.md`](README.md)),
Vivado writes many Verilog netlists under `vivado/stm_bd/`. These are **files generated by Vivado**.
They are not tracked by git (`.gitignore`) and are overwritten every time you synthesize again.
So no comments are written into them; this document explains how to read them instead.

At the top of each RTL file (`rtl/*.v`, `rtl/ch/*.vh`) there is a **【ネットリスト解説】**
("netlist notes", in Japanese) block that explains the circuit the file builds and how its nets
connect. This document continues from there: it shows what parts and connections (the netlist)
the RTL actually became.

The numbers and names below come from a build with Vivado 2022.2, `xc7a35ticsg324-1L` (Arty A7-35)
and `greet_uart.hex`.

## 1. What a netlist is

A netlist is a list of parts (cells) and a list of the wires (nets) that connect the parts' pins.
In the RTL, `assign` and `always` describe *what to compute*. In the netlist, the same logic has been
replaced by real FPGA parts (LUTs, flip-flops, carry chains, block RAMs) and the wires between them.

```verilog
// RTL (rtl/ch/160_op_lb2.vh)
assign OP_B_OPC_NEW = OP_B_STAYS ? OP_B_OPC : OP_B_SHIFT ? OP_WAIT_OPC : ACCEPTING_OPC;
//   + in stm_cntl.v:  always @(posedge clk) ... OP_B_OPC <= OP_B_OPC_NEW;

// Netlist (stm_system_cpu_0_sim_netlist.v)
LUT4 #(.INIT(16'hB8BB)) \OP_B_OPC[0]_i_1          // logic = a 4-input truth table
   (.I0(OP_WAIT_OPC[0]), .I1(p_49_in), .I2(WW_ST_GO), .I3(A_LS_ST_V),
    .O(\OP_B_OPC[0]_i_1_n_0 ));
FDRE \OP_B_OPC_reg[0]                             // flip-flop
   (.C(aclk), .CE(\OP_B_OPC[1]_i_1_n_0 ), .D(\OP_B_OPC[0]_i_1_n_0 ),
    .Q(OP_B_OPC[0]), .R(rst));
```

The `OP_B_STAYS` (hold) branch is gone from the LUT and has moved to the flip-flop's CE
(clock enable) pin. Only the rest, "take it from OP-WAIT or accept a new request", is left in the LUT4.

## 2. Which file is which

Under `vivado/stm_bd/stm_bd.gen/sources_1/bd/stm_system/`:

| File | Contents |
|---|---|
| `hdl/stm_system_wrapper.v` | Top of the block design. Only connects the external ports (clock, reset, UART, switches, `bus_error`) to `stm_system` |
| `synth/stm_system.v`, `sim/stm_system.v` | The block design itself: the IP instances (`cpu`, `smartconnect`, `bram_ctrl`, `ram`, `uart`, `gpio`, `clk_wiz`, `rst`, `reset_pc`) and the AXI wires between them. **The block design diagram written out as a Verilog netlist** |
| `ip/<IP name>/synth/<IP name>.v` | Outer shell of each IP. It instantiates the real design (`stm_axi_top` etc.) |
| `ip/<IP name>/<IP name>_stub.v` | An empty module with port declarations only (a black box). Used to hide the contents when the upper level is synthesized |
| `ip/<IP name>/<IP name>_sim_netlist.v` | **The post-synthesis netlist** (`write_verilog -mode funcsim`). It consists only of connected FPGA parts (UNISIM `LUT6`, `FDRE`, ...) and can be simulated as it is |

Files with the same names also exist under `.cache/ip/...`. That is the cache of IP synthesis results
(almost the same contents; the paths in the headers differ).

Only two of these contain this design (STM): `stm_system_cpu_0` (the CPU, `stm_axi_top`) and
`stm_system_ram_0` (the program memory, `stm_prog_ram`). The rest are Xilinx IPs
(`smartconnect` alone is 110,000 lines), and you don't need to read them.

### Nets of the block design (`synth/stm_system.v`)

Each net is named "<driving instance>_<port>". For example:

```verilog
stm_system_cpu_0 cpu
   (.RESET_PC(reset_pc_dout),              // output of reset_pc (Constant 0x300)
    .aclk(clk_wiz_clk_out1),               // 24 MHz from the Clocking Wizard
    .aresetn(rst_peripheral_aresetn),      // output of the Processor System Reset
    .m_axi_araddr(cpu_m_axi_ARADDR),       // driven by cpu, received by S00_AXI of smartconnect
    ...
```

`cpu_m_axi_*` runs from cpu to SmartConnect, `smartconnect_M00_AXI_*` from SmartConnect to the
BRAM Controller, and `bram_ctrl_BRAM_PORTA_*` from the BRAM Controller to `stm_prog_ram`.

## 3. The CPU netlist (`stm_system_cpu_0_sim_netlist.v`)

### 3.1 Module hierarchy

```
stm_system_cpu_0                    IP shell
└── stm_system_cpu_0_stm_axi_top     rtl/stm_axi_top.v
    ├── stm_system_cpu_0_stm_cntl     rtl/stm_cntl.v + rtl/ch/*.vh (the two stm_exu are flattened into it)
    ├── stm_system_cpu_0_stm_regfile  rtl/stm_regfile.v
    ├── stm_system_cpu_0_stm_icache   rtl/stm_icache.v
    └── stm_system_cpu_0_stm_axi_master rtl/stm_axi_master.v
```

Module names get the IP name (`stm_system_cpu_0_`) as a prefix. `stm_exu` is small, so it is
merged (flattened) into `stm_cntl` and does not appear on its own. The same goes for `function`s
(`stm_defs.vh` etc.): each one becomes part of the logic where it is called.

### 3.2 Kinds and numbers of parts

| Module | FDRE | FDSE | LUT1–6 | MUXF7 | MUXF8 | CARRY4 | Block RAM |
|---|---:|---:|---:|---:|---:|---:|---|
| `stm_cntl` | 1,623 | 0 | 4,286 | 49 | 0 | 65 | none |
| `stm_regfile` | 512 | 0 | 640 | 320 | 64 | 0 | none |
| `stm_icache` | 284 | 6 | 331 | 12 | 6 | 5 | RAMB36E1 × 1, RAMB18E1 × 1 |
| `stm_axi_master` | 136 | 3 | 128 | 0 | 0 | 0 | none |
| `stm_axi_top` (its own logic) | 0 | 0 | 8 | 0 | 0 | 0 | none |

What the parts are:

| Part | Meaning |
|---|---|
| `FDRE` | D flip-flop with CE (clock enable) and **synchronous reset** R (reset value 0) |
| `FDSE` | The same, but with a synchronous **set** S (reset value 1) |
| `LUT1`–`LUT6` | Any logic function of 1–6 inputs. `INIT` is the truth table (bit index = value of the inputs {I5..I0}) |
| `MUXF7` / `MUXF8` | Dedicated muxes that select between two LUT outputs. LUT6 + MUXF7 gives a 7-input function, + MUXF8 an 8-input one |
| `CARRY4` | A fast carry chain for 4 bits. Adders and comparators chain these 4 bits at a time |
| `RAMB36E1` / `RAMB18E1` | Block RAM (36 Kbit / 18 Kbit) |

### 3.3 How names are formed

Synthesis keeps RTL names where it can, so you can trace the netlist back to the RTL.

| Name in the netlist | Meaning | Example |
|---|---|---|
| `X_reg` / `X_reg[i]` | The flip-flop for RTL `reg X` (bit i) | `\PC_reg[0]`, `START_TRIGGER_BAR_reg` |
| `X` | The net on that flip-flop's output (Q) | `OP_B_OPC[0]` |
| `X[i]_i_N` | A LUT that builds the D input of the flip-flop `X[i]`. A larger N is farther from the flip-flop (an earlier stage) | `\PC[0]_i_1`, `\PC[0]_i_2` |
| `..._n_0` | The output net of that LUT / CARRY4 | `\PC[0]_i_1_n_0` |
| `X_NEW` etc. | An RTL wire that survived as a single net | `START_TRIGGER_BAR_NEW` |
| `p_NN_in`, `..._0` | A net whose original name was lost (somewhere inside the logic) | `p_49_in` |
| `func_return` | The return value of a `function` | `add_32_5_20_return[12:9]` |
| `FSM_onehot_X_reg[k]` | The flip-flop for state k after state machine `X` was re-encoded as one-hot | `FSM_onehot_if_st_reg[0]` |
| `g_cache.X` | `X` inside the `generate` block named `g_cache` | `\g_cache.dram_reg` |

### 3.4 Reading some examples

**The PC reset.** In `stm_cntl.v`, the PC is the only register whose reset value is an input, `RESET_PC`.

```verilog
FDRE \PC_reg[0] (.C(aclk), .CE(\PC[31]_i_1_n_0 ), .D(\PC[0]_i_1_n_0 ),
                 .Q(\PC_reg[31]_0 [0]), .R(1'b0));          // R is not used
LUT5 #(.INIT(32'hB8FFB800)) \PC[0]_i_1
   (.I0(TBR[0]), .I1(\PC[31]_i_3_n_0 ), .I2(\PC[0]_i_2_n_0 ),
    .I3(aresetn), .I4(RESET_PC[0]), .O(\PC[0]_i_1_n_0 ));
```

Read as a truth table, `INIT = 32'hB8FFB800` is
`O = !aresetn ? RESET_PC[0] : (I1 ? TBR[0] : I2)`.
Since the reset value is not a constant, the flip-flop's R pin cannot be used (`.R(1'b0)`).
Instead, **logic that selects RESET_PC during reset sits in front of the D input**. The same LUT also
holds the first choice of `PC_NEW = WW_INTERRUPTION ? TBR : ...` (080_w_act.vh).
I1, `PC[31]_i_3`, is

```verilog
LUT5 #(.INIT(32'hFFFFFFFE)) \PC[31]_i_3
   (.I0(W_LS_INTCODE[0]), .I1(W_LS_INTCODE[2]), .I2(W_LS_INTCODE[1]),
    .I3(\W_EX_INTCODE_reg_n_0_[2] ), .I4(\W_EX_INTCODE_reg_n_0_[0] ), ...);
```

a 5-input OR, which is `WW_INTERRUPTION` (= `W_LS_INTCODE != 0 | W_EX_INTCODE != 0`, 050_op_lb1.vh).
`W_EX_INTCODE[1]` is missing because the EX pipe's interrupt code is only ever 1 (illegal instruction)
or 4 (overflow). Synthesis worked out that bit 1 is always 0 and removed that flip-flop (see 3.5).
I2 is the result of the remaining choices (XPC on RFE, MODIFIED_PC on completion, ...).
Other flip-flops (for example `START_TRIGGER_BAR_reg`) use `.R(rst)`, so their reset is just the flip-flop's pin.

**Register file reads.** The muxes inside `stm_regfile` are named after the flip-flops they feed.

```verilog
MUXF8 \A_EX_OP2_DT_reg[0]_i_7 (.I0(...), .I1(...), .O(...), .S(dd_rad2[3]));
MUXF7 \A_EX_OP2_DT_reg[0]_i_8 (.I0(...), .I1(...), .O(...), .S(dd_rad2[2]));
```

The 16:1 mux that picks one word out of `gr_reg[0..15]` with `dd_rad2` (`DD_RAD2` in 030_d_sec.vh)
is a tree of LUT6 → MUXF7 → MUXF8, and it ends at the `A_EX_OP2_DT` flip-flops (140_d_dat.vh).
The RTL path "DD_RAD2 → register file → bypass → A_EX_OP2_DT" shows up directly in the part names.
With 4 read ports and 2 write ports the register file cannot be a RAM, so it became
16 words × 32 bits = 512 FDREs (`gr_reg[k][i]`).

**Adders.** The branch target `DD_TGT` (040_d_bra.vh) goes into the `A_TGT` flip-flops, so there is a chain of
CARRY4s named `A_TGT_reg[..]_i_1`, one for every 4 bits:

```verilog
CARRY4 \A_TGT_reg[12]_i_1 (.CI(\A_TGT_reg[8]_i_1_n_0 ), ..., .O(add_32_5_20_return[12:9]), ...);
```

**The instruction cache RAMs.**

```verilog
RAMB36E1 #(.RAM_MODE("SDP"), .READ_WIDTH_A(72), .WRITE_WIDTH_B(72), ...) \g_cache.dram_reg
RAMB18E1 #(.RAM_MODE("SDP"), .READ_WIDTH_A(36), .WRITE_WIDTH_B(36), ...) \g_cache.tram_reg
```

SDP (Simple Dual Port) means one write port + one read port, which is exactly the shape of the two
`always` blocks in `stm_icache.v`. The data RAM is 64 bits wide (64 of the 72 bits used) × 512,
and the tag RAM is 20 bits wide × 128.

**State machines.** `if_st` in `stm_axi_master.v` (2 bits, 3 states) was rebuilt as the 3 flip-flops
`FSM_onehot_if_st_reg[0..2]` (one-hot). On reset only the IDLE flip-flop becomes 1, so that one is an `FDSE`.

### 3.5 Things in the RTL that are not in the netlist

Nets that nothing uses are removed by synthesis. The RTL keeps them so it still matches the original
CHDL line for line, but you won't find them in the netlist.

* Instruction fields that are never used (`I0_JB_IMM12`, `I0_LS_DISP16`, `ILS_RB`, `IEX_RS2`, ...)
* The simulation probes `E_STAT` / `B_STAT` / `A_STAT` / `D_STAT`
* Flip-flops used only to hold their own value: `W_LATTER_IS_JB`, `E_LS_RADS`, `E_LS_OPS_IS_GR`, `B_EX_RAD2`
* Flip-flops found to be constant: `W_EX_INTCODE[1]` (the EX pipe's interrupt code is either
  `INTCODE_OP` = 1 or `INTCODE_OVF` = 4, so bit 1 is always 0; the same holds for the earlier stages
  such as `E_EX_INTCODE`)

The other way round, flip-flops with no RTL name can appear in the netlist (one-hot state machines,
flip-flops duplicated to reduce fan-out, and so on).

## 4. Program memory (`stm_system_ram_0_sim_netlist.v`)

`stm_prog_ram` (`AW=11`, 8 KB) becomes just 2 `RAMB36E1`s, with no flip-flops or LUTs.
The program read from `INIT_FILE` is embedded in the netlist in hex, as the block RAMs'
`INIT_00`–`INIT_7F` attributes. This is why you have to synthesize again after changing the program.

## 5. Simulating with the netlist

`*_sim_netlist.v` can be simulated with the UNISIM library (behavioural models of `LUT6`, `FDRE`, ...).
The `glbl` module that UNISIM needs is included at the end of the file. With the same testbench as
the RTL, you can check that synthesis did not change the behaviour. (It is `-mode funcsim`, so it has
no delays. As the comment at the top of the file says, it cannot be used for SDF-annotated timing simulation.)
