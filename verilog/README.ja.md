# STM-1.2 ハードウェア記述の Verilog HDL 2001 版

[English](README.md) | **日本語**

`hard/` にある CHDL (`*.ch`) と C ヘッダ (`*.h`) を Verilog HDL 2001 に変換したものです。
元ファイルには手を加えていません。

## 1. 元の記述 (CHDL) について

STM は 2 命令同時発行 (2-way スーパースカラ) の 32bit RISC CPU です。
ハードウェアは **CHDL** という独自の簡易 HDL で書かれています。中身はほぼ C の式で、

| CHDL                | 意味 |
|---------------------|------|
| `NAME = 式`          | 組合せ回路のネット |
| `NAME := 式`         | フリップフロップ (FF) への代入。次のクロックで値が変わる |
| 名前中の `-`          | 普通の文字 (`DD-RAD1` で 1 つの名前) |
| `#` 以降              | コメント (`#ifndef VHDL` などは cpp の指令) |

`soft/chc` + `soft/perlcmd1` が CHDL を C に変換してサイクルシミュレータ `stmsiml` を作ります。
その際 `A := 式` は `A_NEW = 式;` になり、サイクルの最後に `A = A_NEW;` で FF が更新されます。
`*.h` は、その C ソースの先頭に付けるマクロ (ビットフィールド抽出、加算器など) と演算器 `exu()` です。

同じソースを `vh/` のツールで VHDL (Alliance 用) にも変換できるよう、`#ifdef VHDL` で
C 用と VHDL 用の書き方を切り替えている箇所があります。

## 3. 変換のルール

| CHDL / C                                   | Verilog 2001 |
|--------------------------------------------|--------------|
| `DD-RAD1 = 式`                             | `assign DD_RAD1 = 式;` |
| `PC := 式`                                 | `assign PC_NEW = 式;` と `always @(posedge clk) PC <= PC_NEW;` |
| `-` を含む名前                              | `-` → `_` (VHDL 変換ツールと同じ規則) |
| `0xdead0a0a`                               | `32'hdead0a0a` |
| マクロ `ls_store(i)`, `cc_match(cc,m)` …   | 同名の `function` |
| `exu(opc,x,y,&cc,&z,&intr)`                | `stm_exu` のインスタンス (A サイクル用と E サイクル用の 2 個) |
| `GR[..] :=`, `Mem[..] :=`                  | 外部モジュール `stm_regfile` / `stm_memory` |
| `#ifndef VHDL … #else … #endif`            | C 側 (実際に検証されていた方) を採用し、VHDL 側はコメントで残す |
| `#if 0 … #endif`                           | 元でも無効なのでコメントとして残す |
| ビット番号 (MSB=0 番)                       | 一般的な `[31:0]` (LSB=0 番) に変換。`bit_ext(i,s,n)` = `i[31-s -: n]` |

ビット幅は元ソースに書かれていないので、VHDL 変換ツール用の表 `vh/prop.tab` / `vh/assi.tab` から取りました。

**評価順序について**: CHDL→C では文が書いた順に実行されるため、本来は順序に意味があります
(使う前に定義が必要)。全 `.ch` を調べ、すべてのネットが「定義 → 使用」の順に並んでいる
ことを確認したので、順序に依存しない Verilog の連続代入に置き換えても動作は変わりません。

**リセット**: `rst=1` で全 FF を 0、`PC` だけ `RESET_PC` にします。C 版が PC に開始番地を入れ
他を 0 から始めていたのと同じで、`START_TRIGGER_BAR=0` なので最初のサイクルで命令フェッチが始まります。

## 4. 回路の中身 (各 .ch の役割)

パイプラインは **IF → D → A → B → E → W** で、D で最大 2 命令を発行し、
LS パイプ (ロード/ストア、メモリオペランド演算) と EX パイプ (レジスタ演算) と JB (分岐) に振り分けます。

| ファイル | 内容 |
|---|---|
| 010-d-pre | 命令キュー IWQ-A/B (各 6 語) から、次に発行する 2 命令 I0/I1 を取り出す。分岐予測で 2 本の経路を持ち、`EID` がどちらを使うか選ぶ |
| 015-d-i01 | I0/I1 のフィールド解読 |
| 020-d-iss | 各命令が LS/EX/JB/特権のどれか、どのレジスタを読み書きするか |
| 030-d-sec | 2 命令目を同時発行できるか (CC/レジスタ依存、パイプ競合) を判定し、ILS/IEX/IJB に振り分け |
| 035-d-ixx | ILS/IEX/IJB のフィールド解読 |
| 040-d-bra | 分岐: 種類判定 (BA/JA/BL/JL/BC)、条件分岐が既に解決済みか、後方分岐なら taken と予測、分岐先 DD-TGT の計算 |
| 045-g-ram | レジスタファイルとメモリ (Verilog では別モジュール) |
| 050-op-lb1 | S ユニット (オペランドキャッシュ) の出力、割り込み/分岐予測ミスによるキャンセル、アドレス比較割り込み |
| 060-g-srq | 各ステージの有効フラグ、A サイクルのオペランド未到着検出 (A-EAB)、SU への要求の優先度 |
| 070-g-ilk | インタロック条件と各ステージの前進信号 (D/A/B/E-FWD) |
| 080-w-act | W サイクル: システムレジスタ・PC・PSW の更新、割り込み処理 |
| 090-e-act | E サイクル: LS パイプの ALU、割り込みの優先順位、W への受け渡し、ストアバッファ STB |
| 100-b-dat | B サイクル: バイパスを含むオペランド/ロードデータの選択 |
| 110-b-act | B → E の状態遷移、バイト/ハーフワードの opcode をアドレス下位で決定 |
| 120-a-dat | A サイクル: EX パイプの EXU、アドレス生成 (EAG)、システムレジスタ読み出し |
| 130-a-act | A → B の状態遷移 |
| 140-d-dat | D → A へオペランドを渡す。各ステージからのバイパス選択 |
| 150-d-act | D → A の状態遷移 |
| 160-op-lb2 | S ユニットの次状態 (WAIT/B 状態) |
| 170-if-req | 命令フェッチ要求のアドレス/ID |
| 180-if-lbs | 命令フェッチ応答 (キャッシュミス模擬を含む) |
| 190-if-stm | 命令フェッチ状態機械と NIP (キュー内の次命令位置) |
| 200-if-iwq | 命令キュー IWQ のシフト/取り込み |
| 210-g-bc | 条件分岐の解決状態を持つグローバル FF (G-BC-*) |

## 5. 判断が必要だった点 (元ソースとの差)

C 版と VHDL 版で記述が食い違う箇所は、すべて **C 版** に合わせました。C 版が回帰テスト
(`samples/subbup`) で実際に検証されていた方であり、下記の検証でも一致を確認しています。

1. **`is_legal_opc`** (fmt-ls-ex.h): VHDL 版の論理式はユーザーモードを見ず、命令範囲も C 版と少し違う簡略版。C 版を採用。
2. **`WW-STATECHANGE`** (050-op-lb1.ch): C 版は「WSR の書き込み先が 0〜3 番 (PSW 等)」、VHDL 版は逆の条件 (4 番以上) になっている。C 版を採用。
3. **レジスタファイル/メモリ**: C 版では `GR[..] :=` が即座に書き込まれ、同じサイクルの読み出しに反映される
   (write-through)。`stm_regfile` / `stm_memory` で読み出しバイパスを付けて再現。
4. **EXU の未定義動作**: C 版で値を設定しない場合 (未定義 opcode、バイト系命令の cc) は 0 を出力。
   シフト量 32 以上 (C では未定義動作) は SL/SRL → 0、SRA → 符号埋めとした。
5. **乱数によるキャッシュミス模擬** (`random()`): 入力ポート `RANDOM_FOR_OPCLH/IFRDY/IFCLH` にした。
   常に 1 ならキャッシュ常時ヒット、テストベンチの `+RANDOM` で C 版 `stmsiml -r` 相当になる。
6. **シミュレーション用プローブ** (`E-STAT` など) はそのまま wire として残した。

なお、元のアセンブラ `soft/asm.pl` は 32bit perl 前提で、今の 64bit perl では負の変位が
`80aeffff00000000fefc` のように壊れます。マスク計算 1 行だけを直したコピーを `tools/asm64.pl` に置きました。

さらに、Windows の Perl (Strawberry Perl など) は日本語を含むフォルダの中で
`Can't open perl script ...: Unicode 文字のマッピングがターゲットの マルチバイト コード ページにありません。`
というエラーになることがあるため、Python に移植した `tools/asm.py` を用意し、通常はこちらを使う
ようにしました。bup0/bup1/samples の全 67 ファイルで `asm64.pl` と同じ出力になることを確認しています。

## 6. 検証

* `iverilog -g2001 -Wall` で警告なしにコンパイルできることを確認。
* **回帰テスト**: `bup0` / `bup1` の全 64 本を、キャッシュミス無しとランダムキャッシュミス有りの
  両方で実行し、128/128 が SUCCESS (PC=0x3F0) で終了。
* **C 版とのサイクル単位比較**: 元の C シミュレータ (`soft/chc` で生成される `stmsiml`) を
  RISC-V クロスコンパイラ + QEMU で動かし、bup0/bup1 全 64 本と `samples/tst.s` の計 65 本で、
  毎サイクルの PC, 各ステージの FWD, I0/I1, IB-AD, LBS-AD, W-WDT1/2, PSW-CC, NIP-A/B
  を比較 → **全サイクル完全一致**。
  (ランダムモードは乱数列が C の `random()` と異なるため、サイクル比較はしていません)

## 7. 使い方

必要なもの: Python 3 と Icarus Verilog (iverilog / vvp)。Perl は不要です。

### 回帰テスト一式

Windows PowerShell の場合 (verilog フォルダで):

```powershell
powershell -ExecutionPolicy Bypass -File run_bup.ps1
```

Git Bash などの sh の場合:

```sh
sh run_bup.sh
```

### 1 本だけ動かす

```powershell
python tools/asm.py ../samples/tst.s 200 -o mem.dat
python tools/mem2hex.py mem.dat mem.hex          # "PC=300 CYCLES=200" と表示される
iverilog -g2001 -I rtl -o sim.vvp tb/tb_stm.v rtl/stm_sys.v rtl/stm_cntl.v rtl/stm_exu.v rtl/stm_regfile.v rtl/stm_memory.v
vvp sim.vvp +HEX=mem.hex +PC=300 +CYCLES=200 +TRACE
```

* アセンブラの出力は `-o` でファイルに書いてください。PowerShell 5 の `>` は UTF-16 で
  保存されます (`mem2hex.py` は UTF-16 も読めるようにしてありますが、`-o` が確実です)。
* `+RANDOM` (+`SEED=n`) でキャッシュミス模擬、`+CTRACE` で C 版の `siml.res` と同じ形式で出力します。

## 8. AXI4 マスタ版 (`stm_axi_top`)

`stm_axi_top` は、CPU 本体とレジスタファイルに、`stm_memory` の代わりに **命令キャッシュ** と
**AXI4 マスタ** のポートを 1 つ付けた CPU 一式です。命令もデータもこのポートからアクセスします。
データキャッシュはありません。

```
 stm_cntl (EXT_BUS=1) --IB_AD, IB_AD_NXT--> stm_icache --ライン埋め--+
      ^  |  \                                                       v
      |  |   +---------------LBS_* (ロード / ストア)------------> stm_axi_master <==AXI4==> m_axi_*
      |  v GR                                                    (データ 32bit)
 stm_regfile
```

| ポート | 内容 |
|---|---|
| `aclk`, `aresetn` | クロック, リセット (0 でリセット。同期リセットとして扱うので `aclk` に同期して解除すること) |
| `RESET_PC` | リセット後の開始番地 |
| `m_axi_aw*`, `w*`, `b*`, `ar*`, `r*` | AXI4 マスタ (データ 32bit, アドレス 32bit, ID は `ID_W` ビット。`*USER`/`*REGION` は無し) |
| `PC`, `bus_error` | 観測用: 現在の PC / SLVERR・DECERR 応答があったら 1 (sticky)。ロードのエラーは例外にもなる (後述) |

| パラメータ | 既定値 | 意味 |
|---|---|---|
| `ID_W`, `IF_ID`, `OP_ID` | 4, 0, 1 | AXI の ID 幅, 命令フェッチとロード/ストアに使う ID |
| `BYTE_SWAP` | 0 | バイトレーンの並び (後述) |
| `ICACHE` | 1 | 1 = 命令キャッシュあり, 0 = 無し (毎回 8 バイトを読む) |
| `IC_LINE_W` | 5 | ライン = 2^`IC_LINE_W` バイト (4〜6: 16〜64 バイト) |
| `IC_SET_W` | 7 | ライン数 = 2^`IC_SET_W` (既定 32 バイト × 128 = 4KB) |
| `IO_EN`, `IO_BASE`, `IO_MASK` | 1, `F000_0000`, `F000_0000` | I/O 領域 = `(番地 & IO_MASK) == IO_BASE` の番地 (既定は上位 256MB)。`IO_EN=0` で無くす |

### 命令キャッシュ (`rtl/stm_icache.v`)

* ダイレクトマップ, 読み出し専用。データ配列は 64bit 幅 (1 エントリ = CPU が一度にフェッチする
  8 バイト)。データ配列もタグ配列も「書き 1 ポート + クロック同期の読み 1 ポート」の RAM なので、
  FPGA のブロック RAM になります。有効ビットだけは FF です。
* **ヒットは余分なサイクル無し**: CPU に「次のサイクルにフェッチする番地」(`IB_AD_NXT`) の
  出力を足し、キャッシュはそれで 1 サイクル先に RAM を引いておきます。そのためヒットは元の
  `stm_memory` (同じサイクルに応答) と同じタイミングで返り、キャッシュに収まるコードは
  命令フェッチについて元の設計と同じサイクル数で動きます。
* **ミス** のときはそのラインを WRAP バースト 1 回で埋めます。要求した 8 バイトから読み始め、
  その 2 ビートが届いた時点で CPU に返し (early restart)、続く 8 バイトも届いた順に渡すので、
  順に実行するコードはライン埋めの終わりを待ちません。それ以外のヒットはライン埋めが
  終わってから返します。
* 始めたライン埋めは、CPU がフェッチを取り消しても最後まで行います。要求は番地で照合するので、
  キャッシュは CPU 側の要求の切れ目を知る必要がありません。
* ストアとの一貫性は取りません (下の「自己書き換えコード」を参照)。

### I/O 領域

I/O 領域の番地は、読むと状態が変わることのあるデバイスのレジスタとして扱います。

* **ロードを投機的に実行しない**: I/O 領域へのロードは、次の条件がそろうまで A サイクルで
  待ちます。未解決の条件分岐の先にない。B / E に先行する命令が残っていない (割り込みを起こす
  命令がもう無い)。先行するストアがすべて書き終わっている (ストアバッファが空で、S ユニットに
  ST2 が無い)。そのうえでバスに出すので、デバイスへのアクセスは 1 回だけ、プログラム順に
  起きます。待っているロードは先行する命令を待つだけで、先行する命令がこのロードを待つことは
  ないので、デッドロックはしません。I/O 領域以外のロードには影響しません。
* **ストアの前に読まない**: ストアは通常 B サイクルにその語を読みます (サブワードを組み込むため)
  が、I/O 領域ではこの読み出しをしません。I/O レジスタにはワード単位で書いてください
  (サブワードのストアでは残りのバイトが 0 になります)。
* **命令をフェッチしない**: 命令キャッシュは I/O 領域からフェッチせず (先読みでデバイスに
  触れないため)、代わりに不正命令 `0xE0000000` を CPU に渡します。そこへ飛ぶと不正命令例外に
  なり、XPC にその番地が残ります。
* アクセスは `AxCACHE=4'b0000` (Device, non-bufferable) で出します。

防げないケースが 1 つあります。同じ組で I/O ロードの直前に発行した EX 命令がオーバーフローした
場合、その割り込みでロードが取り消される時点で、ロードはもうバスに出ています。

### バスエラー

| エラー応答 (SLVERR / DECERR) になったアクセス | 結果 |
|---|---|
| ロード, ストアの B サイクルの読み出し | **データアクセス例外**: 割り込みコード 3 (未実装の TLB 用に予約されていたコード)、XPC = その命令の番地、**XLA = アクセスした番地**。行き先のレジスタは書かず、ストアも行わない |
| 命令フェッチ | その 8 バイトを不正命令 `0xE0000000` に置き換え、ラインはキャッシュに残さない。実行すると不正命令例外 (コード 1, XPC = その番地)。投機的なフェッチなら捨てられるだけ |
| ストアの書き込み (B 応答) | `bus_error` だけ。CPU ではストアがもう完了しているので、正確に知らせる方法が無い |

どの場合も `bus_error` は 1 になります。

### バスに出るアクセス

| アクセス | チャネル | バースト |
|---|---|---|
| 命令フェッチ, `ICACHE=1` (ライン埋め) | AR/R, `ARID=IF_ID`, `ARPROT=3'b100` (命令) | WRAP, `ARLEN=2^(IC_LINE_W-2)-1` (既定 8 ビート), `ARSIZE=2`, 要求した 8 バイトから |
| 命令フェッチ, `ICACHE=0` (8 バイト = 2 命令) | 同上 | INCR, `ARLEN=1`, 8 バイト境界 |
| ロード, ストアの B サイクルの読み出し | AR/R, `ARID=OP_ID`, `ARPROT=3'b000` | 1 ビート, 4 バイト境界 |
| ストア (ストアバッファからの ST2) | AW/W/B, `AWID=OP_ID` | 1 ビート, `WSTRB=4'hf` |

* バスに出るのは 32bit の語アクセスだけです。サブワードのストアは CPU 内部で語に
  組み立ててから ST2 で書きます。
* 命令側とオペランド側はそれぞれ 1 トランザクションまで同時に出せます。AR チャネルは共用で、
  オペランド側を優先します (ARVALID を出したら ARREADY まで相手は変えません)。
  R のビートは RID で振り分けるので、応答が順不同・インタリーブで返ってきても構いません。
* オペランド側は 1 要求ずつ、R のデータ / B の応答を待ってから次へ進むので、ロードと
  ストアはプログラム順にバスへ出ます。ストアは B 応答が返って初めて完了扱いです。
* `AxCACHE=4'b0011` (normal, non-cacheable, bufferable)。I/O 領域では `4'b0000` (Device)。
  `AxLOCK=0`, `AxQOS=0`。`RREADY` と `BREADY` は常に 1。
* 応答はすべてレジスタで受けてから CPU に渡します (オペランドは `stm_axi_master`, 命令は
  キャッシュの RAM / レジスタ)。AXI の入力から `stm_cntl` への組合せ回路はありません。

### CPU 本体の変更 (`stm_cntl` のパラメータ `EXT_BUS`)

CPU にはもともとキャッシュミス用のハンドシェーク (`RANDOM_FOR_OPCLH/IFRDY/IFCLH`) があるので、
AXI4 版ではこれを「バスのデータが届いた」合図として使います。既定の `EXT_BUS=0` では
動作は以前とまったく同じです (128/128 の回帰テスト, C 版とのサイクル一致もそのまま)。
`stm_axi_top` は `EXT_BUS=1` にしていて、変わるのは次の点です。

1. **ST2 がバスを待つ**: 元は ST2 は必ず 1 サイクルで終わったが、書き込みが完了するまで
   OP-B に留まるようにした (160-op-lb2 の `OP_B_FORWARDING`)。
2. **OP-B の番地によるストア→ロードのフォワーディング**: 元は、STB や E のストアが同じ番地を
   持っていればロードをヒット扱いにし、データは B サイクルのバイパス (`BB_MEM_DATA`) で
   補っていた。バスでは要求が OP-B で何サイクルも待つことがあり、そのころには命令がもう
   B にいないので、`LBS_AD` で直接データを選ぶようにした (050-op-lb1 の `OP_LBS_DATA`)。
   ストアの B サイクルの読み出しも同様。
3. **未解決 BC を発行したら古いフェッチを取り消す** (170-if-req の `CANCEL_IB`):
   未解決の条件分岐の分岐先を取りに行く要求は 1 回しか出ず、フェッチ部が使用中だと消えて
   しまう。元の設計ではフェッチが必ず次のサイクルに終わるので問題にならなかったが、
   フェッチが遅いと分岐先のキューに古いフェッチの続きが入り、予測と違う側のコードを
   実行してしまった。その古いフェッチを取り消してフェッチ部を空け、次のサイクルに
   `D_IF_AD` から分岐先を要求し直すようにした。
4. **I/O ロードを A で待たせる** (060-g-srq の `AA_IO_LD_HOLD`) / **I/O ストアは読まない**
   (050-op-lb1 の `OP_B_IO_ST`)。内容は「I/O 領域」の通り。領域は CPU 本体のパラメータ
   `IO_EN` / `IO_BASE` / `IO_MASK` で決める。
5. **バスエラーでデータアクセス例外**: 読み出しデータと一緒に新しい入力 `MEM_OP_ERR` を受け、
   `OP_B_INTCODE` を `INTCODE_TLB` にする (050-op-lb1)。このコードのとき、E サイクルは
   ロード結果の代わりに番地を `W_WDT1` に渡して W で XLA に保存させ、例外になったストアは
   ストアバッファに入れない (090-e-act)。
6. **ポートの追加**: キャッシュとブリッジ用に、出力 `IB_VALID`, `IB_AD_NXT` (次のサイクルの
   `IB_AD`), `OP_B_NEW`, `OP_B_BUSREQ` と入力 `MEM_OP_ERR`。`stm_sys` では出力は未接続、
   `MEM_OP_ERR` は 0 に固定。

AXI トランザクションを出した後に CPU がロード/ストアを取り消した場合 (分岐予測ミス,
割り込み) は、`stm_axi_master` がトランザクションを最後まで受け取ってから結果を捨てます。

### 性能

SUCCESS までのサイクル数。`stm_sys` は元の (同じサイクルに応答する) メモリで、理想値です。

| プログラム | `stm_sys` | AXI, キャッシュ無し | AXI, 命令キャッシュ 4KB | AXI 乱数ウェイト, キャッシュ無し | AXI 乱数ウェイト, 命令キャッシュ 4KB |
|---|---|---|---|---|---|
| `bench/loop.s` (100 回のループ, 1 回にロード 9 + ストア 1) | 2,218 | 6,737 | **5,047** | 13,408 | **9,397** |
| bup の 64 本 (合計) | 4,275 | 12,157 | **9,180** | — | — |

`bench/loop.s` では、命令フェッチのバス読み出しが 1,208 回から 6 回に減りました。
残りの差はロードとストアで、これらは毎回バスに出ます。bup の各プログラムは短く、ほとんど
初回のミスで終わるので、効果は小さめです。

### 注意点

* **データキャッシュは無い**: ロードとストアは毎回バスに出ます。これが今の主なコストです。
* **I/O 領域以外では投機的に読む**: そこでは予測ミスした側のロードが取り消される前にバスへ
  出ることがあり (元の設計と同じ)、命令の先読みとライン埋めもコードの終わりより先を読む
  ことがあります。読むと状態が変わるデバイスは I/O 領域に置いてください。
* **自己書き換えコードには対応していません**: 命令キャッシュはストアを見ていません。
  命令フェッチとストアの順序も保証しません。
* **ストアの書き込みのエラー** (B 応答) は `bus_error` を立てるだけです (「バスエラー」参照)。
* **バイト順**: STM はビッグエンディアン (番地 4n のバイトが語の最上位)。`BYTE_SWAP=0` では
  CPU の語をそのままバスに載せるので、`$readmemh` の語イメージがそのまま使えます。
  `BYTE_SWAP=1` ではバイトを入れ替え、番地 4n+k のバイトを `xDATA[8k+7:8k]` に置きます
  (AXI の通常のバイトレーンの約束)。リトルエンディアンのマスタや周辺装置とバイト単位で
  メモリを共有する場合はこちらを使います。

### 検証

* `iverilog -g2001 -Wall` で警告なしにコンパイルできることを確認。
* `run_bup_axi.ps1` / `run_bup_axi.sh` で bup0/bup1 の全 64 本を 5 通り
  (4KB キャッシュ + ウェイト無しのスレーブ / 4KB キャッシュ + 乱数ウェイト・読み出し応答の
  順序入れ替え・インタリーブ / 同じく `BYTE_SWAP=1` / 16 バイト × 2 ラインのキャッシュ
  (入れ替えが多い) / キャッシュ無し) で実行し、320/320 が SUCCESS で終了。
* 追加のストレステスト: bup の 64 本と `tests/` の 5 本 × 乱数スレーブの種 20 通りを
  5 つのキャッシュ構成 (4KB, 4KB + `BYTE_SWAP`, 2 × 16 バイト, 4 × 64 バイト, 無し) に
  振り分けて 1380/1380 成功。
  `bench/loop.s` も試したすべての構成で成功。
* 新しい動作のテストを `tests/` に置きました (自己検査で、合っていれば SUCCESS で終わる)。
  スレーブモデルは `F000_0000` にテスト用デバイス (レジスタ A は読まれた回数を返し、レジスタ B は
  最後に書かれた値のビット反転を返す) を持ち、`E000_0000`〜`EFFF_FFFF` には SLVERR を返します。

  | テスト | 確かめること |
  |---|---|
  | `io_order.s` | 予測ミス側の I/O ロードはデバイスに届かない。I/O へのストアはデバイスを読まない。同じ I/O レジスタへのストア直後のロードは、書き込みの後にデバイスを読む (フォワーディングした値ではない) |
  | `load_err.s` / `store_err.s` | エラー応答 → 割り込みコード 3, XPC と XLA が正しい。行き先のレジスタ / メモリは変わらない |
  | `fetch_io.s` / `fetch_err.s` | I/O 領域 / エラーを返す番地へ飛ぶ → 不正命令例外, XPC = その番地 |

  `run_bup_axi.*` は、これらと `bench/loop.s` も bup のプログラムと一緒に 5 通りの構成で実行し、
  350/350 成功。I/O の保護を外す (`IO_EN=0`) と `io_order.s` は失敗する (予測ミス側でデバイスが
  2 回読まれる) ので、このテストで問題を検出できることも確認しました。
* `tb/axi4_mem_slave.v` が毎サイクル、マスタの AXI の規則 (READY まで VALID と内容を保持,
  WLAST とバースト長の一致, 4KB 境界をまたがない, サイズがバス幅以下) を検査し、違反があれば
  テストベンチが `AXIERR` を出します。違反はありませんでした。

### 使い方

```powershell
powershell -ExecutionPolicy Bypass -File run_bup_axi.ps1   # Windows PowerShell
sh run_bup_axi.sh                                          # sh / Git Bash
```

1 本だけ動かす場合:

```powershell
python tools/asm.py bench/loop.s 20000 -o mem.dat
python tools/mem2hex.py mem.dat mem.hex
iverilog -g2001 -I rtl -o axi.vvp tb/tb_stm_axi.v tb/axi4_mem_slave.v rtl/stm_axi_top.v rtl/stm_icache.v rtl/stm_axi_master.v rtl/stm_cntl.v rtl/stm_exu.v rtl/stm_regfile.v
vvp axi.vvp +HEX=mem.hex +PC=300 +CYCLES=20000 +RANDOM +SEED=5
```

`+RANDOM` でスレーブの乱数ウェイト・順序入れ替え、`+TRACE` で毎サイクルの表示、`+VCD` で
`tb_stm_axi.vcd` に波形を出力します。パラメータは `iverilog` に `-P tb_stm_axi.ICACHE=0`,
`-P tb_stm_axi.IC_SET_W=4`, `-P tb_stm_axi.BYTE_SWAP=1` のように付けます。
